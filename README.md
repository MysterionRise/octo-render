# octo-render

A from-scratch Rust software renderer that reimplements the core shape of an OpenGL-style pipeline: OBJ loading, vertex transforms, viewport mapping, triangle rasterization, z-buffering, shader-style fragment evaluation, shadow mapping, and screen-space ambient occlusion.

![Hero render generated by the CPU software renderer](renders/hero.png)

The portfolio story is intentionally split:

- `app` is the CPU software renderer and the main proof of graphics fundamentals.
- `octo-app` is an interactive `wgpu` viewer used as a GPU comparison/demo layer.

Technical notes: [software renderer write-up](docs/software-renderer.md), [case study](docs/case-study.md), and [benchmark methodology/results](docs/benchmarks.md).

## Build And Run

```bash
cargo build --release --workspace
```

Render with the CPU software renderer:

```bash
cargo run --release --bin app -- \
  --model resources/teapot.obj \
  --shader shadow \
  --width 768 \
  --height 768 \
  --output renders/shadow-teapot.png \
  --debug-dir renders/debug/teapot-shadow \
  --cull off \
  --depth-test on \
  --depth-write on
```

Supported CPU shader modes:

```text
wireframe, flat, gouraud, texture, normal-map, normal-debug, shadow, ssao
```

OpenGL-style CPU render-state options:

```text
--cull off|front|back
--front-face ccw|cw
--depth-test on|off
--depth-write on|off
--fill solid|wireframe
--scissor x,y,width,height
--clear-color r,g,b
--clear-depth <z>
--color-write on|off
--texture <path>
--texture-wrap repeat|clamp
--texture-filter nearest|linear
--normal-map <path>
--base-color r,g,b
--ambient <value>
--diffuse <value>
--specular <value>
--shininess <value>
--shadow-size <px>
--shadow-bias <z>
--shadow-filter none|pcf
```

Texture example:

```bash
cargo run --release --bin app -- \
  --model resources/textured-quad.obj \
  --shader texture \
  --texture resources/checker.ppm \
  --output renders/textured-quad.png
```

Normal-map example:

```bash
cargo run --release --bin app -- \
  --model resources/textured-quad.obj \
  --shader normal-map \
  --texture resources/checker.ppm \
  --normal-map resources/normal-checker.ppm \
  --texture-filter linear \
  --light 0,0,1 \
  --ambient 0.05 \
  --output renders/normal-map-quad.png
```

Run the interactive GPU viewer:

```bash
cargo run --release -p octo-app
```

## Pipeline

```mermaid
flowchart LR
    OBJ["OBJ asset"] --> Parse["robust parser\ntriangulation, negative indices"]
    Parse --> Vertex["vertex transform\nmodel, view, projection"]
    Vertex --> Clip["attribute-preserving\nnear-plane clipping"]
    Clip --> Viewport["viewport transform"]
    Viewport --> Raster["barycentric triangle rasterizer"]
    Raster --> State["render state\ncull, depth, fill, sampler"]
    State --> Fragment["fragment shader\nflat, Gouraud, texture, normal map"]
    Fragment --> Shadow["shadow-map pass\nbias, size, PCF"]
    Shadow --> SSAO["SSAO post-process"]
    SSAO --> PNG["PNG output + debug maps"]
```

Implemented CPU features:

- Bresenham line drawing
- OBJ parser for `v`, `vt`, `vn`, and polygonal `f` faces
- Fan triangulation for quads/ngons
- Negative OBJ index support
- Perspective projection and viewport mapping
- Attribute-preserving near-plane clipped-triangle emission
- Barycentric triangle rasterization
- Z-buffer visibility
- Explicit render state: culling, front-face winding, depth test/write, fill mode, scissor, clear state, color write
- Texture sampler wrap/filter modes: repeat, clamp, nearest, linear
- Material controls for base color, ambient, diffuse, specular, and shininess
- Shader-style vertex/fragment trait
- Flat, Gouraud, checker/file texture, normal-map, normal-debug, shadow, and SSAO render modes
- Perspective-correct interpolation for shader varyings
- Configurable shadow-map size, bias, and PCF filtering
- Debug outputs for depth, normals, shadow map, and AO

## Performance Snapshot

Detailed methodology and Criterion results are in [docs/benchmarks.md](docs/benchmarks.md). Short version, rendering `resources/teapot.obj` at `128x128` under Criterion:

| Mode | Triangles | Time | Throughput |
| --- | ---: | ---: | ---: |
| flat | 6,320 | 1.1599 ms | 5.45M triangles/sec |
| Gouraud | 6,320 | 2.7501 ms | 2.30M triangles/sec |
| shadow | 6,320 | 4.9272 ms | 1.28M triangles/sec |

For more systematic measurements:

```bash

```

Benchmarks cover line drawing, z-buffered triangle rasterization, full-frame software renders, clipped vs unclipped triangles, texture filters, shadow filters, and resolution scaling.

## Architecture

The workspace has two layers:

- Root package `octo-render`: CPU software-renderer library (`renderer`) plus the `app` CLI.
- `crates/*`: GPU viewer stack split into core data, asset loading, `wgpu` helpers, renderer passes, and `octo-app`.

The CPU renderer is the OpenGL-style reimplementation. The GPU viewer is intentionally separate because it delegates rasterization to `wgpu`/Metal/Vulkan/DX backends.

## Known Limitations

- Near-plane clipping emits clipped triangles with preserved varyings; full six-plane homogeneous frustum clipping is still future work.
- Texture sampling supports nearest and bilinear filtering, but not mipmaps.
- Normal-map mode consumes a CLI normal-map texture; OBJ/MTL material-library loading is still future work.
- Shadow mapping supports configurable bias and simple 3x3 PCF, but not cascades or slope-scaled bias.
- SSAO is deterministic and useful as a pipeline demonstration, but not physically based.
- The CPU renderer is optimized enough for portfolio evidence, not production real-time rendering.
