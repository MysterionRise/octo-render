# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

A from-scratch Rust CPU software rasterizer that reimplements the core of an OpenGL-style pipeline. It follows the [tinyrenderer](https://github.com/ssloy/tinyrenderer/wiki/) lessons 0-8 and extends them with six-plane frustum clipping, a top-left fill rule, explicit render state, texture sampling with mipmaps, MTL materials, Blinn-Phong specular, shadow mapping with PCF, and SSAO. It renders Wavefront OBJ models to PNG (or any format the `image` crate writes, chosen by the output extension).

A separate `wgpu` viewer under `crates/` is an interactive GPU comparison layer. It is not the CPU proof and shares no code with the CPU renderer.

## Build & Run Commands

- **Build everything**: `cargo build --release --workspace`
- **CPU renderer CLI**: `cargo run --release --bin app -- --model resources/teapot.obj --shader shadow --output out.png` (the binary is `app`; `--help` lists every flag)
- **GPU viewer**: `cargo run --release -p octo-app` (needs a display and a Metal or Vulkan adapter)
- **Lint**: `cargo fmt --check` and `cargo clippy --workspace --all-targets` (CI runs both plus the tests)
- **Tests**: `cargo test --workspace`. CPU renderer tests live in the `#[cfg(test)] mod tests` at the bottom of `src/renderer.rs`; the CLI parser test is in `src/main.rs`. The `crates/*` GPU stack has no tests.
- **Benchmarks**: `cargo bench` (Criterion, `benches/line_benchmark.rs`: lines, triangles, full frames, clipping, texture filters, blending, shadow filters, resolution scaling)
- **Gallery**: `scripts/render-gallery.sh` regenerates every image in `renders/` with the exact commands used for the README.
- **Demo reel**: `scripts/make-demo.sh` renders `examples/demo.rs` (a 21 s, 9:16 storyboard of `render_scene` frames with 2×2 supersampling) and uses ffmpeg (libx264 + drawtext) to add captions, a progress bar, and an end card, writing `renders/demo/octo-render-demo.mp4` and a GIF under 8 MB. `--preview` renders 270×480 into `target/demo-preview/` in seconds. Frames go to `target/demo/`.
- **Golden images**: `UPDATE_GOLDENS=1 cargo test -p octo-render golden` rewrites `tests/golden/*.png` from the current output. Only do this for an intentional pixel change, and inspect the image diff before committing. `tests/golden/legacy-camera-flat-teapot-64.png` is a frozen render from the pre-October-2026 camera; it is compared directly and never re-blessed.

## Architecture

Workspace root package `octo-render`:

- **`src/renderer.rs`** — library crate `renderer`, a single large file:
  - OBJ/MTL loading: `Model::load` / `Model::load_with_options` (`v`/`vt`/`vn`, polygon fan triangulation, negative indices, `mtllib`/`usemtl`), `Model::generate_missing_normals` (welded, angle-weighted, crease-limited smooth normals for corners without `vn`), `ObjMaterial`, `Material`
  - Transforms: `viewport`, `projection`, `lookat`, `transform_point`
  - Raster: `draw_line` (Bresenham), `triangle_shader_perspective_with_state` and wrappers (barycentric coverage, top-left rule, perspective-correct varyings), `clip_varying_triangle_against_frustum` (six planes, preserves source barycentrics)
  - Render state: `RenderState`, `CullMode`, `FrontFace`, `DepthState`, `FillMode`, `ScissorRect`, `BlendMode`
  - `Shader` trait and built-ins: `GouraudShader`, `TextureShader`, `NormalMapShader`, `NormalDebugShader`, `DepthShader`, `ShadowShader`
  - Textures: `TextureSampler`, `sample_texture_with_mipmaps`, `build_mipmaps`
  - `render_scene(&[SceneObject], &RenderOptions, scene_radius) -> RenderOutput` orchestrates a frame: shadow-map depth pass over every object (fixed depth-only state) → main pass per object (each `SceneObject` has its own model-to-scene transform and material, sharing one z-buffer) → SSAO post-process → debug maps → vertical flip. `render_model(&Model, &RenderOptions)` is a scene of one object recentred and scaled to `SCENE_RADIUS` (`SceneObject::normalized`, `normalized_transform`).
- **`src/procedural.rs`** — `renderer::procedural`: meshes generated from math with analytic (or central-difference) unit normals, outward CCW winding, and bit-exact seams and poles: `grid_surface` (shared parametric builder), `ground_grid`, `ground_disk`, `uv_sphere`, `torus`, `torus_knot` (parallel-transport frame), `parametric`, `supershape` (`Superformula`), `twisted_torus` (`TwistedTorus`). Tests weld by exact position and check watertightness, winding, volumes, and normals.
- **`src/main.rs`** — `app` CLI: hand-rolled flag parser, material and texture resolution, writes the image plus optional debug PNGs
- **`benches/line_benchmark.rs`** — Criterion suite
- **`scripts/render-gallery.sh`** — reproducible gallery renders
- **`examples/demo.rs`** + **`scripts/make-demo.sh`** — the demo reel: storyboard segments (view, cast, eased camera orbit, light sweep), per-frame procedural meshes, parallel frame rendering, caption timeline, ffmpeg assembly

`crates/` (GPU viewer): `core` (mesh types), `asset` (its own OBJ loader), `gpu` (wgpu context, buffers, textures), `renderer` (shadow, forward, post-process passes), `app` (the `octo-app` binary, winit + egui), and `shaders/*.wgsl`.

## Conventions

- **Light direction**: `RenderOptions::light_dir` and `--light` give the direction *toward* the light in normalized scene space (default `DEFAULT_LIGHT_DIR`, 1,1,1). `render_model` rotates it into eye space once for shading, and renders the shadow map with an orthographic camera along it, so diffuse, specular, and shadows always agree. The shadow camera scales with the scene radius `r` (`shadow_camera`): half-extent `1.025r`, eye `2r` out, its own near/far planes, `0.5/r` NDC depth per unit; at `SCENE_RADIUS` (2) that is 2.05, 4, and ~32 depth units per scene unit. `--shadow-bias` is in depth units, so one unit is `r/63.75` scene units. `RenderOptions::camera_target` (default the origin) is where the camera looks; the light always aims at the origin. Built-in shaders take the eye-space light.
- **Normals** point outward. `Model::face_normal` assumes counter-clockwise winding (the OBJ convention) and only falls back to +Z for zero-area faces. `Model::load` generates smooth normals for corners without `vn` (crease angle `DEFAULT_CREASE_ANGLE_DEG`, 60°); flat mode always uses face normals.
- **Camera**: `build_transforms` uses `lookat` (eye at the view-space origin) and `perspective` (vertical FOV, aspect-correct, reversed-Z with an infinite far plane, `depth_scale = distance² / 4`), with a margin-free viewport. Default eye `DEFAULT_CAMERA_EYE` (0, 0.5, 6), FOV `DEFAULT_FOV_Y_DEGREES` (45). Near/far are view-space distances from the eye, applied by the clipper; each pass (camera, shadow) carries its own in `RenderTransforms`. The legacy `projection` helper is unused by `render_model`.
- **Depth**: larger z is closer. The z-buffer clears to `-inf` and the depth test passes when `z > current`.
- **No lighting discards**: unlit fragments shade to ambient (or black) and still write depth, so they occlude what is behind them.
- **Scene space**: models are recentred and scaled into a normalized scene before the camera is applied, so `--camera` and `--light` live in that space.

Dependencies: `image` 0.25 (PNG, PNM, TGA, and JPEG codecs only) and `glam` 0.32. OBJ models and textures live in `resources/`; write-ups live in `docs/`.

## Colony-Sim Engine (M1 kernel, M2 fluids and persistence, M3 renderer, M4 colonists)

`docs/colony-engine-design.md` is the research, architecture, and roadmap for a purpose-built 2D colony-sim engine (an Oxygen Not Included-like cell simulation with pixel art) on a thin custom `wgpu` core that will reuse `crates/gpu` and the `crates/app` wiring. Milestones M1 to M4 are implemented under `colony/`; their measured results are in the doc's section 14.

- **`colony/sim`** (`colony-sim`): the deterministic kernel. `fixed.rs` (Q16.16 `Mass`/`Temp`, `q16`, `scale_mag`), `element.rs` (`ElementTable`, ids pack the phase in bits 14–15), `world.rs` (SoA `CellBuffers`, `Grid`, `Stencil`, `Dir` priority order down/left/right/up, `CellOut`, `FLAG_PRESSED`), `chunk.rs` (32×32 scheduling chunks, 3×3 activity rule), `fluid.rs` (buoyancy sort pass for every fluid, and the flux pass: same-element gas flux at K = 1/4, liquids pouring, levelling, and pushing excess at a quarter budget each up to `max_mass`, vacuum winner, sub-floor merge, pressure evacuation of gas pressed by a heavier gas or by a liquid), `heat.rs` (min-conductivity conduction with the quarter-capacity clamp, then phase change with a 3 K hysteresis using the element's `melt`/`boil` and `solid_of`/`liquid_of`/`gas_of` links), `sim.rs` (`Sim::step` = `begin_tick`, `pass_sort`, `pass_flux`, `pass_heat`, `pass_agents`, `end_tick`; per-pass chunk activity; `total_mass` and `total_energy` count cells plus items; `cell_hash` covers cells only and `state_hash` adds the entities; `set_cell` activates the chunk in both activity sets, which every agent edit relies on), `rng.rs` (PCG32), `worldgen.rs` (integer value noise and the seeded `cave` world), `save.rs` (format 2: cells, then `encode_entities`, the arenas with generations and free lists, the job board, and each colonist's state machine, with a table hash and a trailing state hash; version 1 files are rejected), `command.rs` (`Command` incl. `Dig`, `Build`, `CancelOrders`, `SpawnColonist`, `SetPriority`; `LogEntry`, log encoding; `Sim::queue` applies commands at the next tick start and logs them, `Sim::replay` re-runs a log), `scenario.rs` (`gas-mixing`, `settled`, `pressure-burst`, `hot-rock`, `noise`, `pool`, `cave` with a party in its largest walkable component, `crew` = `hall` with 100 colonists and hundreds of dig orders, the pathing benchmark; `by_name_seeded`). M4 adds `entity.rs` (`Arena<T>`, `EntityId` with generations, iteration in index order), `item.rs` (debris `Item`: element, mass, temperature, holder, reservation), `job.rs` (`JobBoard` of `Dig`/`Build` jobs with priority, reservation, three failures then cancelled, pruning), `nav.rs` (`NavGrid`: solid/passable/standing flags, 16×16 blocks, regions as row-major BFS components, drop edges up to `MAX_FALL`, region A*, corridor-restricted local A*, `Goal::{Cell, Adjacent}`, lazy refresh from the processed chunks, `largest_component`), and `agent.rs` (`Colonist` state machine idle/walking/fetching/working/stuck, `MOVE_TICKS`, `DIG_TICKS`, `BUILD_TICKS`, the shared `PATH_BUDGET` of 16 solves per tick with `ASSIGN_BUDGET` 6, `RESCAN_PERIOD`; `Sim::spawn_colonist`, `order`, `cancel_orders`, `set_priority`; the agents pass: nav refresh, gravity, assignment, per-colonist step; a dig spawns an item and sets vacuum, a build displaces the target's fluid into a neighbour with `mix_temp` and places the item). The builtin table has vacuum, oxygen, carbon dioxide, water, sandstone, ice, and steam. Every pass is a gather over a double buffer: a cell writes only itself, and every exchange is computed identically by both endpoints, which is what makes passes parallel-safe (rayon row bands behind the default `parallel` feature), deterministic, and exactly conserving.
- **`colony/headless`** (`colony-headless`): PNG renders of element and temperature maps, and the CLI: `cargo run --release -p colony-headless -- --scenario crew --ticks 300 --threads 1 --profile` (`--profile` times the sort, flux, heat, and agents passes and reports colonists, path solves per tick, and job counts; `--help` lists `--width`, `--height`, `--seed`, `--threads 0` for all cores, `--hash-out`, `--png-dir`, `--png-every`, `--compare A B` for the first divergent tick).
- **`colony/render`** (`colony-render`): `snapshot.rs` (`Snapshot::from_sim`: one packed texel per cell, exact values for the probe, per-chunk dirty flags from `Sim::processed_chunks`, `ColonistPose`/`ItemPose` lists and `colonist_at`), `camera.rs` (`PixelCamera`: integer zoom 1..=8, clamped pan, cursor-anchored zoom, exact screen-to-cell), `palette.rs` (`Luts`), `corners.rs` (dual-grid corner grid for solids), `atlas.rs` (procedural tile atlas, rims only on cell boundaries), `shade.rs` (`shade_pixel`/`cpu_reference`, the CPU twin of the shader; tests hold it to `colony-headless` byte for byte and to `tests/golden/cave-64-200-z2.png`), `gpu.rs` (`CellRenderer`: four integer textures, one uniform, one fullscreen-triangle draw, then the sprite pass; `shaders/cells.wgsl` is validated with naga in a unit test), `sprites.rs` (`sprite_instances`: ground items, colonist bodies coloured by state and interpolated from the cell they left by `progress` and the step-period fraction `alpha_x256`, badges for carried items; `SpriteRenderer`: instanced quads from a storage buffer over `shaders/sprites.wgsl`; `stamp_sprites` is its CPU twin), `headless.rs` (device without a surface, offscreen readback), `host.rs` (`SimHost`: the kernel on its own thread, commands, pause, speed, restart, load, save, latest-snapshot mailbox). `tests/gpu_matches_cpu.rs` compares the GPU render to the CPU reference, and a hall with colonists to the CPU composite, and skips without an adapter.
- **`colony/game`** (`colony-game`): `cargo run --release -p colony-game -- --scenario cave` opens the window (needs a display and an adapter); `--screenshot out.png --ticks 200` and `--benchmark 300` render offscreen at 1080p with any adapter. `main.rs` parser, `app.rs` winit + egui frame loop (sprites rebuilt every frame with the interpolation alpha), `input.rs` key map and the `Tool` enum (`Q` dig, `E` build, `C` cancel, `N` spawn, `P` pour, `O` oxygen; `command_for(tool, x, y)`), `ui.rs` inspector (tool selector, colonist and job counts, path solves, colonist probe), `offscreen.rs`.
- **Tests**: `cargo test -p colony-sim -p colony-headless -p colony-render -p colony-game`. Unit tests sit beside each module; `colony/sim/tests/determinism.rs` pins exact mass conservation, bounded energy drift, identical hashes, parallel-equals-sequential, and chunk skipping; `colony/sim/tests/agents.rs` pins the dig-then-build loop (every job done, no item left, cells plus items constant), floor digging, build displacement, unreachable orders staying open, the per-tick path budget, replay with orders, and the format-2 save round trip; `colony/sim/tests/golden/*.hash` and `colony/headless/tests/golden/*.png` are goldens, re-blessed with `UPDATE_GOLDENS=1 cargo test -p colony-sim -p colony-headless golden` only for an intentional rule change, after inspecting the image.
- **Benchmarks**: `cargo bench -p colony-sim` (`tick/*` per scenario and size, `hash/*`). The `noise` scenario is the all-chunks-active worst case.
- **Rules** (CI enforces the first): `colony-sim` must not depend on `wgpu`, `winit`, or `glam`; its state and tick code use fixed-point integers, never `f32`/`f64` or the wall clock; any rule that needs a third cell's decision is redesigned, not patched with locks (the doc's section 6.8); chunks must stay at least two cells wider than the deepest stencil times the number of passes per tick. In `colony-render`, `shade_pixel` and `cells.wgsl` must stay line-for-line equivalent, as must `stamp_sprites` and `sprites.wgsl`; the GPU parity tests are the check, so run them on a machine with an adapter after touching any of the four. Agent code edits cells only through `Sim::set_cell` and iterates arenas in index order.
